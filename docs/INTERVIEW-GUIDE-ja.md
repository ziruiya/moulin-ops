# 面接官向けガイド

ローカルの `http://localhost:8080` に `demo-viewer` でログインすると、記録を読みながら以下の順で確認できます。編集・承認も試す場合はそれぞれ `demo-operator`、`demo-reviewer` に切り替えます。セットアップとアカウントの変数名は README を参照してください。 [Quick Start](../README.md#09-quick-start) · [Demo Accounts](../README.md#10-demo-accounts)

## 1. ダッシュボード

「緊急リスク」で、公開 EC の PHP 8.1 のサポート終了や、模擬通報で影響が確認されたコンポーネントを開きます。「データ要確認」「バックアップと復元」「変更管理」では、それぞれ判断に必要な情報と次に対応する項目が異なります。「今日の作業リスト」は障害・脆弱性・メンテナンス枠を表示します。 [UI-01](screenshots/ui-01.png)

## 2. PHP のサポートが終了した資産

「IT資産」で `DEMO-EC-WEB-01` を検索し、資産詳細を開きます。PHP 8.1.34 は独立したコンポーネントとして登録されています。版の情報源、公開 EC との関連、他資産への依存と、ベンダー・外部サポート連絡先・チケットの参照欄を確認します。 [資産一覧](screenshots/ui-02.png) · [資産詳細](screenshots/ui-03.png)

## 3. ライフサイクルの情報源

PHP の行でサポート段階、確認日 `2026-11-18` と `OFFICIAL_MANUAL_SEED` に対応する手動登録表示を確認します。通常サポートとセキュリティサポートの終了日は別欄です。「確認履歴」は当時の導入版・確認日時・引用元を保持します。日付が不明または情報が古いコンポーネントは「終了日不明」「要再確認」と表示します。 [PHP のサポート終了一覧](https://www.php.net/eol.php) · [PHP のサポート中の系列](https://www.php.net/supported-versions.php)

## 4. 更新計画

「更新・変更管理」から `CHG-2026-001` を開きます。一覧、状態別、時間表示から同じ計画を参照できます。変更理由は PHP 8.1 の EOL で、PHP 8.5.x は互換性を検証する候補です。対象資産と PHP コンポーネント、担当 Operator、Reviewer の承認履歴を確認します。 [UI-05](screenshots/ui-05.png)

## 5. リスクとチェックリスト

同じ計画の Critical の理由と、影響調査、事前検証、バックアップと復元準備、実施、実施後の確認の五段階を確認します。十三の項目では、事前検証の証跡と確認担当を後から追えます。脆弱性の扱いを見る場合は「脆弱性管理」の `DEMO-VUL-2026-001` で、対象式、導入版、影響判定と処理状態を比較します。`DEMO-VUL-2026-005` は範囲を解析できない例です。 [UI-04](screenshots/ui-04.png)

## 6. バックアップとロールバックの実施条件

`CHG-2026-001` は事前検証が合格、バックアップが完了、復元検証が未確認です。保留の元の段階は実施予定であり、そこへ戻しても復元確認がなければ実施中への遷移は拒否されます。`CHG-2026-003` ではロールバック自体の失敗から `DEMO-INC-2026-001` へ進み、障害と変更計画の関連を確認できます。別の HTTP テストでは、旧版の復元を確認してロールバック済みになる経路を再現しています。 [変更管理](CHANGE-MANAGEMENT-ja.md) · [UI-06](screenshots/ui-06.png)

## 7. 作業と監査の記録

「この計画の作業記録」を開き、計画で絞り込んだタイムラインからバックアップや実施記録を確認します。障害詳細からは同じ障害に関連する作業へ移動できます。「監査記録を検索」で対象の種類、ID、日付を指定し、状態変更や承認者を確かめます。 [UI-07](screenshots/ui-07.png)

## PHP 保守の個人練習

Laravel のデモと別に、依存パッケージなしで動く PHP の修正例を二つ用意しています。いずれも最初の仮説を実行結果で反証し、修正前と修正後に同じテストを実行します。

1. 在庫数量の `0` が欠損扱いになる例。整数と CSV 由来の文字列の両方を確認します。 [ケース 1](php-maintenance-case-study-ja.md#ケース-1-在庫数の-0-が未入力になる)
2. UTC の受信時刻を東京の日付で集計する例。日付境界と年末年始を確認します。 [ケース 2](php-maintenance-case-study-ja.md#ケース-2-utc-の受信時刻が東京の前日に集計される)
